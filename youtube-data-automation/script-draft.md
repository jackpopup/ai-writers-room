## 2. 인트로 — 문제 정의 (0:30 ~ 2:00)

[화면: 유튜브 스튜디오 → 스프레드시트로 수동 복붙하는 화면 재현]

유튜브 채널 운영하시는 분들, 이 루틴 익숙하시죠?

유튜브 스튜디오 열고, 조회수 확인하고, 스프레드시트에 숫자 옮기고.
매일 5분이면 되니까 대수롭지 않게 느끼는데요.

1년이면 30시간입니다. 꼬박 하루하고도 6시간.

[화면: "매일 5분 × 365일 = 30시간" 텍스트 애니메이션]

그리고 이건 유튜브만 그런 게 아니에요.
GA4 트래픽, 인스타 인사이트, 광고 플랫폼 성과 데이터.
전부 똑같은 복붙 노동입니다.

오늘 보여드릴 건 유튜브 스튜디오 데이터를 Google Sheets로 자동 수집하는 시스템인데요,
방법을 알면 다른 데이터도 같은 방식으로 자동화할 수 있습니다.

그리고 이 영상에서는 "어떻게"보다 "왜"에 집중합니다.
왜 이 방식을 골랐는지, 왜 중간에 바꿨는지.

그 판단 과정이 진짜 핵심이거든요.

## 3. 본론 1: 기획 (2:00 ~ 5:00)

[화면: 빈 Google Sheets + OKR 프레임워크 그래픽]

자동화 시작할 때 가장 많이 하는 실수가 뭔지 아세요?

바로 코드부터 짜는 겁니다.

"자동화할 수 있다"와 "자동화해야 한다"는 완전히 다른 문제예요.
수집할 수 있는 데이터가 100개라고 100개 다 수집하면, 그건 자동화가 아니라 디지털 쓰레기통이에요.

그래서 저는 OKR 프레임워크부터 잡았습니다.

[화면: OKR 구조도 — 북극성 지표 → 핵심 지표 5개]

OKR이 뭐냐. Objective, 목표가 있고, 그걸 측정할 Key Results, 핵심 지표가 있는 거예요.
제 북극성 지표는 "구독자 20,000명"이었고, 이걸 추적하려면 뭘 봐야 하는지 다섯 개를 뽑았습니다.

구독자 수, CTR — 그러니까 썸네일 클릭률이죠 — 시청완료율, 주간 조회수, 일일 구독자 증감.

이 기획을 제가 혼자 한 게 아니라, Claude Code한테 시켰어요.
`/pdca plan`이라는 명령어로 "유튜브 데이터 자동 수집 기획해줘" 하니까 이 구조를 잡아줬습니다.

[화면: Claude Code 대화 화면 — /pdca plan 명령어와 응답]

그다음 단계가 API 조사였는데요.
API, 쉽게 말하면 데이터 자판기예요. 동전 넣고 버튼 누르면 데이터가 나오는 기계.

유튜브에는 두 개가 있어요. Data API v3하고 Analytics API v2.
Data API는 조회수, 구독자 같은 기본 데이터, Analytics API는 시청완료율 같은 심층 데이터를 줍니다.

[화면: API 비교표]

근데 여기서 벽을 만났습니다.

CTR, 썸네일 클릭률. 이건 유튜브 스튜디오에서만 볼 수 있고, API로는 안 줍니다.
아무리 뒤져봐도 방법이 없어요.

[화면: 텍스트 — "CTR: API 미제공 ❌"]

여기서 판단이 필요했어요. "어떻게든 가져올 방법을 찾는다" vs "깔끔하게 빼고 간다".

저는 뺐습니다.

[화면: 천천히 — CTR에 줄 긋는 애니메이션. 0.5초 정적]

수집 가능한 것만 자동화한다. 이게 완벽주의를 버리는 의사결정이었고, 빼는 판단이 프로의 증거라고 생각합니다.

5개 중 4개. 충분합니다.

## 4. 본론 2-A: 설계 (5:00 ~ 8:30)

[화면: 기술 비교표 — Python vs n8n vs Apps Script]

기획이 끝났으니 이제 "뭘로 만들지" 정할 차례입니다.

딱 세 갈래가 있었어요.

첫째, Python. 가장 강력하죠. 근데 서버가 필요해요. 코드 돌릴 컴퓨터를 24시간 켜놓거나 클라우드 서버를 빌려야 합니다. 매달 돈 나갑니다.

둘째, n8n이나 Make 같은 자동화 플랫폼. 레고 블록처럼 끼워 맞추는 방식인데, 무료 범위가 좁아요. 쓸 만하려면 월 과금이 필요합니다.

셋째, Google Apps Script. 이건 엑셀 매크로의 구글 버전이라고 보시면 돼요. Google Sheets 안에 내장되어 있고, 무료고, 시간 되면 자동으로 실행하는 트리거 기능도 있습니다.

[화면: Apps Script 항목에 체크 표시]

유지비 0원. 별도 서버 불필요. 시트 안에서 완결.
고민할 것도 없었어요.

자, 기술을 골랐으니 이제 설계입니다.
Claude Code한테 `/pdca design` 명령을 줬어요.

[화면: Claude Code 대화 화면 — 설계 요청과 결과물]

그랬더니 801줄짜리 설계문서가 나왔습니다.

[화면: 설계문서 스크롤 — 801 lines 표시]

7개 .gs 파일 구조.
4개 시트 설계 — Config, Data, OKR Dashboard, Charts.
함수 이름, 데이터 흐름, 에러 처리 방식까지 다 잡혀 있었어요.

잠깐, 여기서 진짜 중요한 게 뭐냐면요.

코드를 모르는 제가 설계문서를 만들었다는 겁니다.

[화면: 텍스트 자막 — "코드를 모르는 사람이 801줄 설계문서를 만들었다"]

제가 한 건 "뭘 수집할지"와 "어떤 기술로 할지"를 정한 것뿐이에요.
나머지 구조는 AI가 잡았습니다. 이게 AI 협업의 핵심이에요.
방향만 잡아주면 됩니다.

## 5. 본론 2-B: 구축 (8:30 ~ 12:00)

[화면: GCP 콘솔 화면]

설계가 끝났으니 이제 진짜 만듭니다. 딱 4단계예요.

[화면: "4단계" 카운트다운 그래픽]

**하나**, GCP 프로젝트 생성.

[화면: 타임랩스 — GCP 콘솔에서 프로젝트 만들고 YouTube API 활성화하는 과정. 30초로 압축]

GCP, Google Cloud Platform이요. 구글 API를 쓰려면 여기서 프로젝트를 하나 만들어야 해요.
프로젝트 만들고, YouTube Data API 활성화하고, OAuth 설정까지.
OAuth는 "이 앱이 내 유튜브 데이터에 접근해도 됩니다"라는 허가증이라고 보시면 돼요.

화면 보면서 따라하시면 되는데, 클릭 몇 번이면 끝납니다.

참고로, 채널 관리자인 경우에는 소유자가 초기 설정 함수를 한 번만 실행해주면 됩니다.

**둘**, Claude Code와 대화하면서 코드 생성.

[화면: Claude Code 대화 화면 — 코드 생성 과정 하이라이트]

여기가 재밌어요. 한 번에 "다 만들어줘"라고 안 했습니다.

"Config 시트 읽는 함수 먼저 만들어줘."
결과 확인하고.
"이번엔 YouTube Data API 호출하는 함수."
결과 확인하고.
"이제 OKR 대시보드에 계산 결과 쓰는 함수."

[화면: 파일이 하나씩 쌓이는 애니메이션 — 7개 .gs 파일]

이렇게 단계별로 대화하니까 7개 파일, 1,345줄 코드가 만들어졌습니다.

왜 한 번에 안 시켰냐고요?
한 번에 시키면 AI가 중간에 맥락을 놓쳐요. 하나씩 확인하면서 쌓아가는 게 결과물 품질이 훨씬 좋습니다.

**셋**, clasp로 배포.

[화면: 터미널 — clasp push 명령어]

clasp는 뭐냐. 로컬 컴퓨터에서 만든 코드를 Google Apps Script로 올려주는 도구예요.
USB 꽂아서 파일 옮기는 것처럼, 명령어 하나면 코드가 올라갑니다.

`clasp push` 딱 한 줄이에요.

**넷**, 테스트.

[화면: Apps Script 에디터에서 실행 버튼 클릭 → Google Sheets에 데이터 채워지는 화면]

실행 버튼 누르고... 잠깐 기다리면...

[화면: 0.5초 정적]

Data 시트에 숫자가 채워집니다.

됐어요.

[화면: 텍스트 — "91% Gap Analysis 통과"]

설계문서 대비 구현 검증도 했습니다. Gap Analysis라고, 설계한 32개 항목 중 29개가 그대로 구현됐어요. 91% 일치율.
완벽하진 않지만 충분히 믿을 수 있는 수준입니다.

## 7. 아웃트로 (14:30 ~ 16:00)

[화면: 다른 서비스 로고들 — GA4, Instagram, Google Ads, Meta]

이게 유튜브에서만 되는 게 아닙니다.

GA4 트래픽? Google Analytics API 연결하면 같은 방식으로 자동 수집됩니다.
광고 플랫폼? Google Ads API, Meta Marketing API. 구조가 똑같아요.
API라는 데이터 자판기에 동전만 바꿔 넣으면 됩니다.

[화면: 프로젝트 요약 인포그래픽]

이번 프로젝트 정리해 드릴게요.

5세션 대화.
801줄 설계문서.
1,345줄 코드, 7개 파일.
설계 대비 91% 구현, 32개 검증 항목 중 29개 통과.

[화면: 숫자가 순서대로 나타나는 애니메이션]

제가 직접 한 건요?
방향을 정하고, 벽에 부딪힐 때 우회로를 고른 것뿐입니다.

코드 한 줄 안 썼다고 했죠? 그건 사실이에요.
근데 오해하시면 안 되는 게, 아무것도 안 한 건 아닙니다.
뭘 수집할지 정하고, 어떤 기술로 할지 고르고, 안 되는 걸 빼는 판단을 한 거예요.
AI가 코드를 짰지만, 의사결정은 사람이 했습니다.

그리고 솔직히 말하면 Apps Script도 만능은 아니에요. 실행 시간 6분 제한이 있고, 복잡한 데이터 처리에는 한계가 있습니다. 근데 이 정도 수집 자동화에는 충분하고도 남습니다.

[화면: 다시 이메일 리포트 화면 — 훅에서 보여줬던 그 장면]

처음에 보여드렸던 이 화면, 기억나시죠?
이제 이게 어떻게 만들어졌는지 아시잖아요.
여러분 업무에도 반복해서 복붙하고 있는 데이터, 분명 있을 겁니다.
AI한테 시키세요.

이 영상이 도움이 되셨다면 좋아요, 구독 부탁드리고요.
"나는 이런 데이터를 자동화하고 싶다" 댓글로 남겨주시면 다음 영상에서 다뤄보겠습니다.

그럼 다음 영상에서 뵙겠습니다.
