# 구성안 (Outline): 유튜브 데이터 자동 수집 영상

**예상 총 길이**: ~16분 (대본 기준 약 4,800자 내외)
**콘텐츠 유형**: 튜토리얼/다큐 하이브리드

---

## 구성 (7개 섹션)

### 1. 훅 (0:00 ~ 0:30) — 30초

**완성물 먼저 보여주기 + 충격 한 방**

- (화면) 완성된 OKR 대시보드, 차트, 이메일 리포트 빠르게 보여줌
- "이걸 만드는 데 코드를 한 줄도 직접 안 썼습니다."
- "근데 5일 걸렸습니다. 왜냐면 — 3번 방향을 바꿔야 했거든요."
- **약속**: "이 영상을 끝까지 보시면, 여러분도 본인 업무에 맞는 자동화를 AI한테 시킬 수 있게 됩니다."

**핵심 WHY**: 왜 이 영상을 봐야 하는가

---

### 2. 인트로 — 문제 정의 (0:30 ~ 2:00) — 1분 30초

**반복 노동의 고통 공감 + 적용 범위 제시**

- 유튜브 스튜디오 → 스프레드시트 수동 복붙의 일상
- "매일 5분이 1년이면 30시간" — 숫자로 체감
- 유튜브 말고도: GA4, 인스타 인사이트, 광고 플랫폼, 매출 데이터
- 오늘 예시: 유튜브 스튜디오 → Google Sheets 자동화
- "이 영상에서는 '어떻게'보다 '왜'에 집중합니다. 왜 이 방식을 골랐는지, 왜 중간에 바꿨는지."

**핵심 WHY**: 왜 자동화가 필요한가 (시간의 가치)

---

### 3. 본론 1: 기획 — "뭘 수집할지 정하기" (2:00 ~ 5:00) — 3분

**OKR 프레임워크로 지표 선정 → API 현실 조사**

- 왜 목표부터 세워야 하는가: "자동화할 수 있다"와 "자동화해야 한다"의 차이
- OKR 프레임워크 소개: 북극성 지표 → 핵심 지표 5개 선정 과정
  - 구독자, CTR, 시청완료율, 주간 조회수, 일일 구독자 증가
- Claude Code에게 /pdca plan으로 기획 요청한 과정
- API 조사: YouTube Data API v3 vs Analytics API v2
- **현실 부딪힘**: CTR은 YouTube Studio 전용, API로 못 가져옴
- "수집 가능한 것만 자동화" — 완벽주의를 버리는 의사결정

**핵심 WHY**: 왜 "뭘 수집할지"를 코드 전에 정해야 하는가
**의사결정 포인트**: 5개 중 CTR을 제외한 이유

---

### 4. 본론 2-A: 설계 — "AI와 구조 잡기" (5:00 ~ 8:30) — 3분 30초

**기술 스택 선택 + 대화로 설계문서 만들기**

- 기술 선택의 갈림길: Python vs n8n/Make vs Google Apps Script
  - Python: 강력하지만 서버 필요
  - n8n/Make: 쉽지만 월 과금 + 제한
  - Apps Script: 무료 + 구글 시트 네이티브 + 트리거 내장
- "왜 Apps Script인가" — 유지비 0원, 별도 인프라 불필요, 시트 안에서 완결
- Claude Code에게 /pdca design으로 설계 요청 → 801줄 설계문서
  - 7개 .gs 파일 구조
  - 4개 시트 설계 (Config, Data, OKR Dashboard, Charts)
  - 함수 시그니처 + 의사코드
- "코드를 모르는 내가 설계문서를 만들었다" — AI 협업의 핵심 가치

**핵심 WHY**: 왜 바로 코딩하지 않고 설계부터 하는가
**의사결정 포인트**: 3개 기술 중 Apps Script를 고른 이유

---

### 5. 본론 2-B: 구축 — "AI와 코드 만들기" (8:30 ~ 12:00) — 3분 30초

**GCP 설정 → 코드 생성 → 배포 → 테스트의 실제 과정**

- GCP 프로젝트 생성 + YouTube API 활성화 + OAuth 설정
  - 화면 공유하며 어디를 클릭하는지 보여줌
- Claude Code와 대화하며 코드 생성하는 과정
  - "이런 함수가 필요해" → 코드 생성 → 수정 요청 → 반영
  - 7개 .gs 파일이 만들어지는 과정 하이라이트
- clasp CLI로 Apps Script에 배포하는 과정
  - 로컬에서 코드 관리 → push로 배포하는 워크플로우
- 테스트 실행 → 데이터 수집 확인
- **참고**: 채널 소유자가 아니라 관리자인 경우, 소유자가 초기 설정 함수를 한 번 실행해줘야 합니다 (Analytics API 권한 특성)
- 91% Gap Analysis 통과 — 설계 대비 구현 검증

**핵심 WHY**: 왜 AI에게 한 번에 다 시키지 않고 단계별로 대화하는가
**의사결정 포인트**: clasp 워크플로우를 선택한 이유 (웹 에디터 vs 로컬 개발)

---

### 6. 본론 3: 완성물 시연 — "이게 매일 자동으로 됩니다" (12:00 ~ 14:30) — 2분 30초

**결과물을 하나씩 보여주며 가치 입증**

- **Data 시트**: 영상별 일일 조회수, 시청완료율, 구독자 변동
  - "어제 데이터가 자동으로 들어와 있다"는 경험의 임팩트
- **OKR 대시보드**: 목표 대비 달성률 + 진행바
  - 구독자 20,000명 목표 대비 현재 위치
- **차트**: 조회수 트렌드, 구독자 성장 추이 시각화
- **이메일 리포트**: 매일 아침 자동 발송되는 요약 메일
- 91% Gap Analysis 통과 — "완벽하진 않지만 충분히 믿을 수 있는 수준"

**핵심 WHY**: 왜 대시보드와 이메일 리포트까지 만들었는가 (데이터는 보여야 의미가 있다)
